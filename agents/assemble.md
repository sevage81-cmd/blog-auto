# Assemble Agent

> `image-make` 에이전트가 이미지 경로까지 다 채워 넣은 draft.md를 받아서,
> 검토용 최종 마크다운과 시각 미리보기용 HTML을 만드는 에이전트다.

---

## 역할

- 입력:
  - `output/[주제]/draft.md` — 이미지 마커가 전부 실제 경로(`![설명](./images/...)`)로
    치환된 상태의 최종 초안
  - `output/[주제]/images/` — 대표 이미지·본문 이미지가 들어있는 폴더
- 출력:
  - `output/[주제]/final.md` — 검토용 마크다운
  - `output/[주제]/final.html` — 시각 미리보기용 HTML
- 목적: 발행 직전 사람이 눈으로 검토할 수 있는 최종 산출물을 만든다.

---

## 왜 스크립트 방식인가

final.md는 draft.md 내용을 그대로 옮기는 파일이고, final.html도 같은 내용을
고정된 스타일(본문 폭 700px, 위계별 폰트 크기 등)로 감싸기만 하면 된다.
그런데 예전에는 이 단계마다 LLM이 이미 완성된 글 전체를 두 번(final.md 한 번,
final.html 한 번) 처음부터 다시 썼다 — 내용은 그대로인데 CSS까지 매번 새로
디자인하느라 시간도 걸리고, 실행마다 스타일이 미묘하게 달라졌다. 이제 이
단계는 `agents/scripts/build_final.py`가 처리한다: draft.md를 그대로 복사해
final.md를 만들고, 고정 CSS 템플릿에 내용만 채워 final.html을 만든다.

---

## 작동 방식

1. **draft.md를 읽는다.** 이미지 경로는 이미 마크다운 이미지 문법
   (`![설명](./images/파일명.png)`)으로 박혀있는 상태이므로, 마커를 다시
   찾거나 치환하는 작업은 하지 않는다.
2. **`agents/scripts/build_final.py` 한 번 실행으로 final.md/final.html을
   모두 생성한다.**
   ```
   python agents/scripts/build_final.py "output/[주제]"
   ```
   - draft.md의 `# 제목`, 문단, `## 소제목`, `![설명](경로)` 이미지,
     `| ... |` 표, 마지막 줄의 `#해시태그 ...` 를 인식해서 처리한다.
   - draft.md에 이 스크립트가 못 알아보는 구조(중첩 리스트, 코드블록, 인용문
     등 write.md/style-guide.md에서 쓰지 않는 마크다운)가 섞여 있으면, 해당
     블록이 `<p>` 안에 원문 그대로 뭉쳐 들어간다.
3. **final.html을 열어서 실제로 확인한다.** 스크립트가 처리하지 못한 구조가
   없는지, 이미지가 다 제대로 걸렸는지, 표가 깨지지 않았는지 눈으로 검토한다.
   - 문제를 발견하면 **draft.md를 직접 고치지 말고** — 그 부분만 수동으로
     final.md/final.html에 반영한다 (draft.md는 write/image-make 단계의
     산출물이므로 assemble 단계에서 되돌아가 고치지 않는다).
   - 예외가 반복적으로 나오는 마크다운 구조라면, 스크립트에 케이스를
     추가하는 게 맞다는 신호이니 사용자에게 알린다.

---

## 반드시 지킬 것

- draft.md의 내용(문장, 이미지 선택, 순서)을 임의로 바꾸거나 새로 창작하지
  않는다. 이 에이전트는 "조립·렌더링" 담당이지, 글을 다시 쓰는 단계가 아니다.
- 이미지 경로는 `output/[주제]/images/` 기준 상대 경로로 정확히 연결한다
  (깨진 링크가 없어야 한다).
- final.html은 외부 CDN/폰트/스크립트에 의존하지 않고, 로컬에서 더블클릭
  또는 `file://` 경로로 열었을 때도 정상적으로 보이도록 만든다.
- 스크립트 실행 후 눈으로 확인하는 3단계를 생략하지 않는다 — 스크립트는
  정해진 마크다운 패턴만 처리하므로, 확인 없이 넘어가면 깨진 결과물을
  놓칠 수 있다.

---

## 산출물

- `output/[주제]/final.md`
- `output/[주제]/final.html`

작업이 끝나면 사용자에게 **`final.html`을 브라우저로 열어서 확인해보라고
안내한다** (파일 경로를 함께 제시한다).
